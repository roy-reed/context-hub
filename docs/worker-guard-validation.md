# Pi / DeepSeek worker 保护验收

状态日期：2026-09-05。

本轮只在独立合成 Git 仓库和本地确定性测试端点中运行，没有向 worker 提供 Context Hub
数据、既有记忆、个人文件或凭据。真实提供商用例仅验证既有 Pi / DeepSeek 调用链和预算
记账；故障注入用例仍经过真实 Pi CLI，但把提供商端点替换为本机测试服务。

## 已确认

| 场景 | 执行面 | 结果 |
|---|---|---|
| 1,000,000 token 任务上限 | 真实 Pi + DeepSeek V4 Pro | 任务接受 `maxTotalTokens=1000000`，单次成功，实际累计 4,923 tokens；`1000001` 被配置校验拒绝 |
| 累计 token 终止 | 真实 Pi + DeepSeek V4 Flash | 任务预算 1,000，首个提供商响应报告 2,977 tokens 后标记 `token-budget`，不重试且未改动仓库 |
| 最终文本截断 | 真实 Pi CLI + 本地确定性兼容端点 | 原始 71,703 字符，只持久化前 65,536 字符，并记录 `finalOutputTruncated=true` |
| 瞬态失败重试 | 真实 Pi CLI + 本地确定性兼容端点 | 连续注入 HTTP 503；第一次判为 `transient-failure` 并重试，第二次因 `attempt-limit` 停止，共 2 次且未改动仓库 |
| 超长任务保护 | 真实 Pi CLI + 本地确定性兼容端点 | 1 分钟共享墙钟预算在约 60.9 秒触发 `wall-time`，不重试且未改动仓库 |

调度器的 14 项 Node 回归测试全部通过，覆盖上限/默认值、跨尝试累计预算、重试分类、
写入后禁止重试、永久错误、保护性终止、64 KiB 截断和安全文件名。

## 解释边界

- 1,000,000 是任务内所有尝试共享的累计预算上限，不是单次模型响应的输出上限，也不
  表示本轮人为消耗了 1,000,000 tokens。
- Pi 只能在提供商返回 usage 后得到本次精确消耗，因此累计 token 保护可能超出阈值至多
  一个提供商响应；一旦识别超限，任务会失败并禁止重试。严格的请求前硬切断仍需上游
  提供商支持每次请求的 token 限额。
- 本地故障注入用于可重复地验证截断、503 重试和墙钟终止，不冒充真实 DeepSeek 故障。
- 任务结果只保留有界助手文本和必要诊断；完整思考内容不会进入交付报告。
